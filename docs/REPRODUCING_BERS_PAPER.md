# Reproducing the BERS paper (Ocean Engineering, OE-D-26-09120)

This repository contains the open-source workflow for the authors' experiments
in _BERS: A Continuous Hybrid Evolutionary–Variational Algorithm for Maritime
Weather Routing with Just-in-Time Arrival_. It includes the synthetic
benchmarks, CMA-ES and FMS optimization tools, analytical vessel-consumption
models, experiment configurations, validation and interval-certificate
scripts, data instructions, and the scripts behind the paper's tables and
figures.

The immutable results release is `ocean-engineering-release`. It is the code
release associated with the revised numerical tables and figures and contains
the corresponding `pyproject.toml`, `uv.lock`, and organized script layout used
below.

The scope is deliberately limited to results produced by the authors. The
scores and reported runtimes of other SWOPP3 participants are historical
benchmark information supplied by the organizers and are not regenerated by
this repository.

## 1. Environment

```bash
git clone https://github.com/IEResearchDatalab/routetools.git
cd routetools
git checkout ocean-engineering-release
uv sync --frozen   # Python 3.12; exact packages are pinned by uv.lock
```

The synthetic experiments and the local-optimality checks run on a CPU. The
full real-ocean sweep requires the 2024 ERA5 files and was run on a Linux
server with an NVIDIA RTX A6000 GPU.

## 2. Components

| Component                             | Where                                                   |
| ------------------------------------- | ------------------------------------------------------- |
| CMA-ES stage (Bézier routes)          | `routetools/cmaes.py`                                   |
| FMS refinement                        | `routetools/fms.py`                                     |
| Land mask, penalty and rollback       | `routetools/land.py`, `routetools/fms.py`               |
| Weather penalties                     | `routetools/weather.py`                                 |
| Vessel performance model (Appendix D) | `routetools/performance.py`, `docs/parametric_model.md` |
| Energy integration                    | `routetools/cost.py` (`cost_function_rise`)             |
| SWOPP3 corridors and passage times    | `routetools/swopp3.py`                                  |

The performance model is an open analytical reconstruction of the SWOPP3
evaluator. Its agreement with the original compiled evaluator is tested in
`tests/test_parametric_model.py`.

## 3. Data

The real-ocean experiments use ERA5 reanalysis for 2024 (10 m wind,
significant wave height, mean wave direction) over the two SWOPP3 corridors.
The exact ERA5 and land-geometry inputs used for the paper are archived at
<https://zenodo.org/records/23470870>. Their checksums and the release above
define the paper inputs. To obtain fresh ERA5 subsets from the upstream public
archives instead, run:

```bash
uv run scripts/data/download_era5.py              # Google Cloud ERA5 archive, no key
uv run scripts/data/download_era5.py --backend cds  # or the Copernicus CDS API
```

The downloaded files are written to `data/era5/` with the names the run scripts
expect. Fresh downloads are useful for independent checks but are not a
byte-for-byte substitute for the archived paper inputs. Natural Earth 1:10m
coastline data are also open and are downloaded and cached automatically by
Cartopy when the land-mask or polygon checks first run.

as `scripts/paper/synthetic/config_land.toml` and `config_noland.toml`.

| Tables 3, 6; Figures 2–4 | Run `uv run scripts/paper/synthetic/results.py --experiment noland` and `uv run scripts/paper/synthetic/results.py --experiment land`, then `uv run scripts/paper/synthetic/figures.py` and `uv run scripts/paper/synthetic/tables.py`. |
| Table 5 (seed dispersion)                         | `uv run python scripts/paper/revision1/task2_synthetic_dispersion.py`                                         |

### Real-ocean corridors (Section 4)

The paper-pinned CMA-ES launchers are:

```bash
sbatch scripts/swopp3/hpc/swopp3_slurm_atlantic_k10.sh
sbatch scripts/swopp3/hpc/swopp3_slurm_pacific_k15_p400.sh
```

These launchers document the exact published settings but contain site-specific
SLURM and data paths that must be adapted to the target server. After combining
their completed case folders as `output/sweep_combined`, run the published FMS
stage:

```bash
bash scripts/swopp3/run_fms_sweep_combined_strict.sh
```

The resulting `output/sweep_combined_fms_strict` directory is the route root
used by the revision analyses below.

Post-processing (no route is re-optimized) is mapped below to the final
manuscript numbering. Labels are included to make the mapping robust to later
typesetting changes.

| Final paper item | Reproduction or audit entry point |
| --- | --- |
| Table 10 (`tab:rw-speeds`), Figure 7 (`fig:rw-speeds`) | `uv run python scripts/paper/revision1/task1_speed_distribution.py` |
| Tables 11–12 (`tab:rw-summary`, `tab:rw-paired`) and Appendix input-range audit | `uv run python scripts/paper/revision2/task1_out_of_domain_audit.py analyze` |
| Table 13 (`tab:rw-common-functionals`) | `uv run python scripts/paper/revision2/task2_common_functionals.py` |
| Figure 10 (`fig:rw-paired`) | `uv run python scripts/paper/revision1/task3_paired_improvements.py` |
| Table 15 (`tab:rw-violations`), Figure 12 (`fig:rw-violation-curves`) | `uv run python scripts/paper/revision1/task4_weather_violations.py` |
| Final seasonal table and figures, including Table 14 and Figures 1, 8, 9, and 11 | `uv run python scripts/paper/revision2/followup_verification.py` after the Task 1 and Task 2 evidence exists |
| Raster-mask results and independent polygon audit | `uv run python scripts/paper/revision1/task7_landfree_export.py`, then `uv run python scripts/paper/revision1/task7_land_verification.py` |
| Operating-envelope Hessian (Appendix E) | `uv run python scripts/paper/revision1/task9_envelope_hessian.py` |
| Final manuscript-to-evidence check | `uv run python scripts/paper/revision2/c3_consistency_check.py --manuscript-root <manuscript-directory>` |

`scripts/paper/revision1/run_revision_postprocessing.sh` and
`scripts/paper/revision1/run_revision_local_optimality.sh` run these steps in order and
record provenance (git commit, host, settings).

The post-processing scripts take the generated route directories as explicit
arguments. Before producing the final tables, create the polygon-checked export
and verify it:

```bash
uv run python scripts/paper/revision1/task7_landfree_export.py \
  --input-dir output/sweep_combined_fms_strict \
  --output-dir output/sweep_combined_fms_strict_landfree
uv run python scripts/paper/revision1/task7_land_verification.py \
  --real-ocean-dir output/sweep_combined_fms_strict_landfree \
  --output-dir output/sweep_combined_fms_strict_landfree/audit \
  --no-include-synthetic
```

The export script copies unflagged routes unchanged, records every local
coordinate correction in `land_repair_manifest.json`, and aborts unless the
final segment--polygon audit finds zero crossings. This audit is independent of
the raster mask used during optimization, but neither representation is a
general navigational-safety guarantee. Both are resolution-dependent and omit
clearance, bathymetry, traffic, and other operational hazards.

## 5. Historical benchmark reference

The documented reproduction workflow uses the open analytical performance
model in `routetools/performance.py`; the historical compiled SWOPP3 evaluator
is not required. Randomized validation against that evaluator found agreement
to 0.103 kW maximum absolute error (0.031% relative), so it serves only as an
independent validation reference. Other participants' scores are held by the
SWOPP3 organizers and appear in the paper only as external benchmark context,
not as outputs that must be regenerated.
